    macOS¶

    macOS is a development-and-test target, not a production target. Use it to build, run objectio-aio, and point Spark / PyIceberg / boto3 at a local S3 endpoint. The split-service OSD binary runs on macOS, but Darwin does not expose the same raw-disk semantics as Linux (O_DIRECT, ioctl BLKGETSIZE64) and the storage engine has no hardened path for APFS-backed OSD disks. Keep macOS deployments to AIO mode or a Docker-hosted cluster.

    Both Apple Silicon (arm64) and Intel (x86_64) are supported. Erasure coding uses the pure-Rust SIMD backend on arm64 and ISA-L on x86_64; wire format is identical.

    1. AIO binary (recommended)¶

    This is the fastest path and the one you'll actually want 95% of the time on macOS.

    Apple Silicon¶

    curl -L -o objectio-aio \
  https://github.com/object-io/objectio/releases/latest/download/objectio-aio-darwin-arm64
chmod +x objectio-aio && sudo mv objectio-aio /usr/local/bin/

    Intel¶

    curl -L -o objectio-aio \
  https://github.com/object-io/objectio/releases/latest/download/objectio-aio-darwin-amd64
chmod +x objectio-aio && sudo mv objectio-aio /usr/local/bin/

    Gatekeeper¶

    Unsigned release binaries will be quarantined by Gatekeeper on first run. Either remove the quarantine attribute:

    xattr -d com.apple.quarantine /usr/local/bin/objectio-aio

    or, on the first launch, open System Settings → Privacy & Security and click Allow Anyway next to the objectio-aio entry.

    Run it¶

    objectio-aio --data "$HOME/.objectio"

    Banner prints the admin AK/SK. --data is optional but recommended — without it, every restart wipes the data tempdir.

    2. Docker Desktop (AIO container)¶

    If you already have Docker Desktop and want zero host install:

    docker run --rm -p 9000:9000 \
  -v objectio-data:/var/lib/objectio \
  ghcr.io/object-io/objectio:latest objectio-aio --data /var/lib/objectio

    On Apple Silicon, Docker Desktop pulls the linux/arm64 image automatically — EC falls back to pure Rust (no emulation). On Intel, you get the ISA-L path.

    For the full 10-container compose cluster (3 meta + 6 OSD + 1 gateway), see docker.md.

    3. Build from source (contributor path)¶

    Only needed if you're hacking on ObjectIO itself.

    Toolchain¶

    # Rust
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh -s -- -y
source "$HOME/.cargo/env"
rustup toolchain install 1.93

# Build deps via Homebrew
brew install nasm autoconf automake libtool llvm protobuf cmake

# Node 22+ for the console SPA (only if you need /_console/)
brew install node@22

    nasm is Intel-only (drives ISA-L assembly). On Apple Silicon, Homebrew still installs it and the build script ignores it.

    Build¶

    git clone https://github.com/object-io/objectio
cd objectio

# Apple Silicon — pure-Rust EC (ISA-L is x86-only)
cargo build --workspace --release

# Intel — ISA-L
cargo build --workspace --release --features isal

    Console¶

    If you want the React /_console/ UI baked into objectio-aio:

    cd console && npm ci && npm run build
cd .. && cargo build --workspace --release    # rebuild to embed dist

    Run¶

    ./target/release/objectio-aio --data "$HOME/.objectio"

    What does not work on macOS¶

    • Production OSDs on raw disks. Darwin's /dev/disk* devices don't support the same O_DIRECT / BLKGETSIZE64 interface the storage engine uses. The OSD binary builds and runs against file- backed "disks" (truncate -s 10G disk0.raw), which is fine for unit tests but not for durability-sensitive work.
    • NBD / block-gateway targets. The block gateway terminates iSCSI / NBD from Linux initiators; macOS has no native initiator for either. Use Linux peers for block-storage testing.
    • io_uring performance path. Linux-specific. Not a correctness issue, but macOS performance numbers are not representative.

    For any of these, run ObjectIO in a Linux VM (Lima, UTM, Colima, Docker Desktop's Linux VM, or a dedicated machine).

    Typical dev loop on macOS¶

    # 1. Run AIO in one terminal, persistent data dir
objectio-aio --data "$HOME/.objectio"

# 2. Point your tool at it
export AWS_ACCESS_KEY_ID=...  # printed in the AIO banner
export AWS_SECRET_ACCESS_KEY=...
export AWS_ENDPOINT_URL=http://localhost:9000

# 3. Work against S3 / Iceberg / Delta Sharing
aws s3 ls
curl -s http://localhost:9000/iceberg/v1/config | jq .

# 4. Console (browser)
open http://localhost:9000/_console/

    Shut down with Ctrl-C — AIO drains cleanly. The data directory is reusable across restarts.

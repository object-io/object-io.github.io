    Audit Stream¶

    Every request to the gateway becomes one audit event: who made it, from where, what it did, and how it ended. The operator streams all of them to their own systems (a SIEM, a log pipeline), and each tenant can stream its own to its own. This is ObjectIO's answer to S3 server access logging, delivered as a stream instead of log objects in a bucket.

    The event¶

    One JSON object per request:

    {
  "version": 1,
  "id": "6F1C0D3A9B2E4F7C8D1A2B3C4D5E6F70",
  "time": "2026-10-02T13:04:11.482Z",
  "api": "s3",
  "method": "PUT",
  "path": "/acme-data/reports/q3.parquet",
  "action": "s3:PutObject",
  "bucket": "acme-data",
  "key": "reports/q3.parquet",
  "bucket_tenant": "acme",
  "principal": {"user_id": "…", "arn": "arn:objectio:iam::acme:user/etl",
                "access_key": "AKIA…", "tenant": "acme", "auth": "Permanent"},
  "source": {"ip": "10.244.3.17", "endpoint": "internal", "user_agent": "aws-sdk-go-v2/1.30"},
  "status": 200,
  "request_bytes": 1048576,
  "response_bytes": 0,
  "duration_ms": 41,
  "complete": true
}
    field
    id The request ID. The client got the same value in x-amz-request-id, and in the RequestId of an error body.
    api s3, admin, console, sts, iceberg, unity, delta-sharing
    action The action as policies name it (s3:GetObject, s3:PutBucketPolicy, sts:AssumeRoleWithWebIdentity). Absent for admin and console calls; read method and path instead.
    bucket, key, bucket_tenant What it acted on, and that bucket's tenant
    principal.auth Permanent (an access key), Sts, AssumedRole, Anonymous, Console, or absent when the request was refused before an identity was established (a bad signature, for example)
    source.ip The client, behind trusted proxies
    source.endpoint The named listener it arrived on
    status, error_code HTTP status and S3 error code (AccessDenied, NoSuchKey, …)
    request_bytes, response_bytes Bytes in (from Content-Length) and out (counted as sent)
    duration_ms, complete Time to the last byte, and whether the whole response went out. false means the client hung up mid-transfer.

    Refused requests are events too: a denied anonymous read or a request with a wrong signature is recorded with its status and error code.

    Never recorded: the Authorization header, and a presigned URL's X-Amz-Signature, X-Amz-Credential and X-Amz-Security-Token, which are replaced by ******** in query.

    Where events go¶

    A file on the gateway host¶

    objectio-gateway --audit-log /var/log/objectio/audit.log   # or "-" for stdout

    The file gets every event as JSON lines, and is reopened when log rotation moves it away. It's set only on the command line (or OBJECTIO_AUDIT_LOG): a host path is not something an API caller should choose.

    The operator's targets¶

    PUT /_admin/audit
{
  "enabled": true,
  "include_reads": true,
  "targets": [
    {"type": "webhook", "name": "siem", "url": "https://siem.example/objectio",
     "auth_token": "…", "batch_size": 500, "flush_ms": 2000, "queue_size": 10000},
    {"type": "stdout", "name": "stdout"}
  ],
  "allowed_tenant_hosts": ["siem.acme.example", "*.logs.globex.example"]
}
    • webhook receives POSTs of application/x-ndjson (one event per line), with Authorization: Bearer <auth_token> when a token is set.
    • stdout writes to the gateway's standard output, for Kubernetes log collection.
    • include_reads: false drops GET and HEAD events, which are most of the volume on a read-heavy cluster.
    • allowed_tenant_hosts lists the hosts tenants may send their own events to (below).

    Every gateway re-reads the configuration within 10 seconds; the one that took the change applies it at once. GET /_admin/audit reads it back with tokens as ********. Writing that placeholder back keeps the stored token.

    A tenant's targets¶

    A tenant admin configures the same way, for its own tenant:

    PUT /_admin/audit           # as acme's admin
{"targets": [{"type": "webhook", "name": "acme-siem",
              "url": "https://siem.acme.example/ingest", "auth_token": "…"}]}

    A tenant receives the events on its buckets, including the operator's own requests on them, and by its principals. It never sees another tenant's.

    A tenant's webhooks must be https and on a host the operator lists in allowed_tenant_hosts. Without that rule, a tenant could point the gateway at addresses inside the cluster, such as meta's port or a cloud metadata endpoint. Redirects are never followed, for the same reason. If the operator later removes a host, delivery to it stops.

    Delivery¶

    • At least once. A webhook batch is retried with backoff (1 s up to 30 s) until the receiver takes it with a 2xx. A receiver can therefore see an event twice; deduplicate on id.
    • Bounded. Each target has a queue (queue_size, default 10 000). If a receiver is down long enough to fill it, new events for that target are dropped and counted. They are never dropped silently, and the request is never held up or refused because of auditing.
    • In memory. Events waiting for delivery live in the gateway. A gateway that crashes loses what it hadn't delivered yet. If you need every event, also keep --audit-log on local disk and collect that.
    metric
    objectio_audit_events_total{target} delivered
    objectio_audit_dropped_total{target} dropped because a queue was full (target="ingest": the gateway's own intake)
    objectio_audit_delivery_failures_total{target} failed delivery attempts (each retried)

    Alert on objectio_audit_dropped_total increasing.

    SDKs¶

    admin.put_audit_config({"targets": [{"type": "webhook", "name": "siem", "url": "https://siem.example/x"}],
                        "allowed_tenant_hosts": ["siem.acme.example"]})

    _, err := admin.PutAuditConfig(ctx, "", objectio.AuditConfig{
    Targets: []objectio.AuditTarget{{Type: "webhook", Name: "siem", URL: "https://siem.example/x"}},
})

    Kubernetes¶

    ObjectIO ships a first-class Helm chart at deploy/helm/objectio/ in the source repo. It wraps every component — gateway (Deployment), meta (StatefulSet, 1 or 3+ pods with Raft bootstrap Job), OSD (StatefulSet with per-pod PVCs), optional block-gateway, optional Prometheus + Grafana — into one release.

    This page is the operator-side walkthrough. For a kubectl demo on a laptop, use the Kind path at the bottom.

    Prerequisites¶

    • Kubernetes 1.26+ (kubeVersion in Chart.yaml)
    • Helm 3.11+
    • A StorageClass that supports ReadWriteOnce and, ideally, WaitForFirstConsumer binding (so OSD pods schedule on nodes with real local disks). Cloud defaults (EBS gp3, PD-SSD, Premium-LRS) work; local-path / Rancher local provisioner is fine for testing only.
    • For ingress: an ingress controller (NGINX, Traefik) or a Gateway API implementation.
    • If you want the k8s-native host-lifecycle provider (gateway admin API Add Host / Reboot OSD), the chart creates its own ServiceAccount + Role. Your cluster just needs RBAC enabled.

    No external dependencies (etcd, ZooKeeper, Redis) — meta is a self-contained Raft cluster.

    Installing the chart¶

    The chart isn't in a public Helm repo yet. Install from a checkout:

    git clone https://github.com/object-io/objectio
cd objectio

helm install objectio ./deploy/helm/objectio \
  --namespace objectio --create-namespace \
  --values my-values.yaml \
  --wait --timeout 10m

    Check it came up:

    kubectl -n objectio get pods
# NAME                              READY   STATUS
# objectio-gateway-<hash>           1/1     Running
# objectio-meta-0                   1/1     Running
# objectio-meta-1                   1/1     Running
# objectio-meta-2                   1/1     Running
# objectio-osd-0 … objectio-osd-5   1/1     Running

    Expose the gateway however your cluster does it — NodePort, LoadBalancer, or kubectl port-forward:

    kubectl -n objectio port-forward svc/objectio-gateway 9000:9000
# then:  aws --endpoint-url http://localhost:9000 s3 ls

    The first admin AK/SK is written by the post-install job to a Secret named objectio-admin-creds (keys: AWS_ACCESS_KEY_ID, AWS_SECRET_ACCESS_KEY).

    values.yaml reference¶

    The chart has a wide surface. These are the stanzas you'll actually touch; the full default is in deploy/helm/objectio/values.yaml in the source repo.

    Scale and durability¶

    ec:
  k: 4            # data shards
  m: 2            # parity shards

meta:
  replicas: 3     # 1 = single-voter (dev); 3+ = real Raft (prod)

osd:
  replicas: 6     # must be >= k + m; set to k+m+spare for repair headroom

    Minimum OSD replicas for common EC profiles:

    Profile OSDs Spare recommended
    4+2 6 7
    8+4 12 14
    10+4 (LRC) 14 15

    Gateway¶

    gateway:
  replicas: 2                          # stateless, scale for throughput
  noAuth: false                        # true only for dev
  region: us-east-1
  externalUrl: https://s3.example.com  # used by Iceberg vended creds + Delta Sharing presign
  ingress:
    enabled: true
    className: nginx
    hosts:
      - host: s3.example.com
        paths: [{ path: /, pathType: Prefix }]
    tls:
      - hosts: [s3.example.com]
        secretName: s3-tls
  oidc:
    issuerUrl: https://keycloak.example.com/realms/objectio
    clientId: objectio
    clientSecret: ""      # or via existingSecret
    adminRoles: objectio-admin
  sse:
    enabled: true         # generates + mounts OBJECTIO_MASTER_KEY on first install
  topology:
    region: eu-west-1
    zone: eu-west-1a
    datacenter: dc1
    rack: ""              # usually auto-derived from node topology labels
  hostProvider:
    enabled: true
    kind: k8s             # lets /_admin/osds/*/reboot actually reboot pods
  # Name the endpoints, for policies that depend on where a request came
  # from (aws:SourceVpce). With external.port set, the ingress targets that
  # port, so pods (the Service on 9000) and the outside (the ingress) arrive
  # on different, named endpoints.
  endpoints:
    internalName: internal
    external:
      port: 9010
      name: external
  # The ingress controller's pod network: its X-Forwarded-For and
  # X-Forwarded-Proto are believed (aws:SourceIp, aws:SecureTransport).
  trustedProxies: "10.244.0.0/16"

    New buckets start with public access blocked, and a bucket can be readable without keys from inside the cluster only. See Public Access.

    OSD — failure domains and persistence¶

    Each OSD pod gets two PVCs: a data PVC (holds the disk.raw backing file, or gets mounted over by a hostPath device) and a small state PVC (WAL + superblock copy). Sizing the data PVC drives cluster capacity.

    osd:
  replicas: 6
  failureDomain:
    region: eu-west-1
    datacenter: dc1
    rack: rack1           # override per-node via pod topology labels
  storage:
    diskFile: disk.raw    # blockSize: leave unset (the OSD's 4 KiB)
  persistence:
    data:
      size: 1Ti
      storageClass: gp3
    state:
      size: 5Gi
      storageClass: gp3
  resources:
    requests: { cpu: "1",  memory: 2Gi }
    limits:   { cpu: "4",  memory: 8Gi }

    For bare-metal / local-disk OSDs, use a local or topolvm StorageClass with volumeBindingMode: WaitForFirstConsumer so each OSD schedules on a node whose disk it can bind to. Cloud EBS-style classes work out of the box.

    Meta — Raft¶

    meta:
  replicas: 3                    # 1 or 3+; do not use 2 or other even numbers
  persistence:
    size: 50Gi
    storageClass: gp3
  resources:
    requests: { cpu: "500m", memory: 1Gi }
    limits:   { cpu: "2",    memory: 4Gi }

    The chart includes a meta-raft-bootstrap-job that runs once on first install. It waits for all meta-* pods to become ready, then issues the Raft membership seed RPC against meta-0. Re-running helm install on a pre-existing release is idempotent; the Job detects an already-bootstrapped cluster and exits.

    Block gateway (iSCSI / NBD)¶

    Opt-in; off by default.

    blockGateway:
  enabled: true
  replicas: 1
  advertiseHost: block.svc.cluster.local   # hostname initiators will attach to
  cacheBytes: 268435456                    # 256 MiB write cache
  service:
    type: LoadBalancer                     # NBD is TCP — must be reachable
    nbdPort: 10809

    Monitoring¶

    Self-contained Prometheus + Grafana stack. Off by default; turn on for quick demos. For real deployments, point your existing Prometheus at the /metrics endpoints (ServiceMonitor templates are in the chart).

    monitoring:
  enabled: true
  grafana:
    adminPassword: "<rotate-me>"
  prometheus:
    retention: 30d
    persistence: { size: 50Gi }

    Storage class guidance¶

    Disk topology StorageClass Notes
    Cloud block storage (EBS gp3, PD-SSD) default PVC = 1 disk = 1 OSD
    Local NVMe via local-static-provisioner local-storage, WaitForFirstConsumer pin OSDs to disk-owning nodes with nodeAffinity
    Local NVMe via TopoLVM topolvm-provisioner LVM-backed, dynamic
    Ceph RBD on the same cluster don't You're storage-on-storage; use ObjectIO directly

    Avoid putting OSDs on NFS / object-backed volumes — the storage engine's durability contract assumes local-ish block semantics.

    Scaling an existing release¶

    # Add OSDs (e.g. 6 → 9 for 8+4 EC)
helm upgrade objectio ./deploy/helm/objectio -n objectio \
  --reuse-values \
  --set osd.replicas=9 \
  --set ec.k=8 --set ec.m=4

    Meta cluster membership changes (1 → 3, or replacing a meta pod) are coordinated by the chart's meta-raft-bootstrap-job on upgrade. Changes to OSD count trigger a rebalance; see operations/failure-recovery.md for progress + throttling knobs.

    Losing a meta pod¶

    With three metas, any one pod can go (killed, evicted, rescheduled, or rolled by kubectl rollout restart) without losing anything the gateway acknowledged. If it was the leader, the other two elect one in about 5 seconds; writes that arrive meanwhile get 503 ServiceUnavailable, which S3 clients retry, and resume on their own. The pod comes back on its PVC and catches up. Losing two of three at once stops writes until one returns: keep the PodDisruptionBudget (meta.podDisruptionBudget) on.

    Uninstalling¶

    helm uninstall objectio -n objectio
# PVCs are NOT deleted by default — protects against accidental data loss:
kubectl -n objectio delete pvc -l app.kubernetes.io/instance=objectio
kubectl delete namespace objectio

    Kind (local Kubernetes) walkthrough¶

    deploy/kind/setup.sh is a one-shot script that stands up a 3-node Kind cluster (1 control-plane + 2 workers), builds every image, loads them into the cluster, installs the chart with a Kind-tuned values.yaml, port-forwards the gateway to localhost:9000, and runs a smoke test covering S3 + Iceberg + Delta Sharing.

    # Prereqs: docker, kind, kubectl, helm
git clone https://github.com/object-io/objectio
cd objectio

make kind-up                                 # build + deploy from source
# OR
make kind-up-registry                        # pull from ghcr.io/object-io (no local build)

    If something already listens on port 9000, forward the gateway elsewhere: PF_PORT=19000 make kind-up.

    To check meta HA on it, with S3 traffic running from a pod: kill the meta leader's pod, then a follower's, then roll the StatefulSet; every acknowledged write must read back.

    deploy/kind/meta-ha-test.sh

    When it finishes, the script prints:

    Endpoints (via kubectl port-forward):
  S3 / Iceberg / Delta Sharing  http://localhost:9000
  Grafana                       http://localhost:3000   (admin / objectio)

EC scheme: 4+2  |  Meta: 3 nodes  |  OSDs: 6 nodes

    Teardown and re-deploy¶

    make kind-down             # delete the whole Kind cluster
make kind-load             # rebuild images + reload into a running cluster
kubectl -n objectio rollout restart statefulset/objectio-osd  # pick up new images

    Why Kind defaults may not match prod¶

    • EC 4+2 on a 3-node Kind means multiple OSDs per node — failure domains are enforced at disk (PVC) level, not host.
    • standard StorageClass is Kind's local-path provisioner. Fine for tests, unusable for real durability.
    • Gateway has noAuth: true — SigV4 is disabled. Never promote this values file to a real cluster.

    For a production-realistic K8s install, use the main deploy/helm/objectio/values.yaml with your own overrides as shown above.

    Troubleshooting¶

    OSD pods stuck Pending¶

    Usually a PVC that can't bind. kubectl -n objectio describe pvc — most common causes: no default StorageClass, or WaitForFirstConsumer + nodeAffinity can't find a matching node.

    meta-0 crash-loops with "node not in cluster"¶

    The raft-bootstrap Job didn't complete. Check:

    kubectl -n objectio logs job/objectio-meta-raft-bootstrap
kubectl -n objectio get pods -l app.kubernetes.io/component=meta -o wide

    All three meta pods must be Ready before the Job issues the seed RPC. If the Job failed (e.g. network policy blocking pod → pod traffic), re-run it:

    kubectl -n objectio delete job objectio-meta-raft-bootstrap
helm upgrade objectio ./deploy/helm/objectio -n objectio --reuse-values

    kubectl port-forward drops connections¶

    Use a Service of type: LoadBalancer (on clouds) or a proper ingress in production. port-forward is for dev only.

    Linux¶

    Linux is the primary production target. Both amd64 and arm64 are first-class — amd64 gets hardware-accelerated erasure coding via ISA-L, arm64 uses a pure-Rust SIMD implementation. Wire format is identical; you can mix architectures in a cluster.

    This page covers the three installation paths, in increasing order of commitment:

    1. Release binaries — drop-in objectio-* binaries
    2. objectio-install — automated node bootstrap with systemd units
    3. From source — Rust toolchain, for contributors

    If you just want a quick local endpoint, use objectio-aio — one binary, no daemons. The rest of this page is about real multi-process / multi-node deployments.

    System requirements¶

    Component Minimum Recommended
    Kernel 4.19+ 5.15+ (for io_uring)
    CPU 2 cores 8+ cores
    RAM 4 GB 16+ GB (OSD), 8 GB (meta), 4 GB (gateway)
    Disks (OSD) 1 × any block device 4+ dedicated raw disks per OSD node
    Network 1 Gbps 10+ Gbps (especially between OSDs)

    Filesystem: OSDs prefer raw block devices (/dev/sdb, /dev/nvme0n1). File-backed disks (/mnt/.../disk.raw) work but skip the O_DIRECT fast path and lose some durability guarantees. Disks are formatted with ObjectIO's own on-disk layout (superblock + WAL + blocks), not ext4/xfs — mkfs-ing first is not required and is not recommended for production OSDs.

    Kernel features used:

    • O_DIRECT on raw block devices (required for OSD disks)
    • ioctl BLKGETSIZE64 for disk sizing
    • io_uring when available (5.15+); falls back to threaded I/O

    Supported distributions: any glibc 2.31+ (Ubuntu 22.04+, Debian 12+, RHEL 9+, Amazon Linux 2023, Rocky/Alma 9+). For older glibc, build from source.

    1. Release binaries¶

    Released binaries are statically linked except for glibc and OpenSSL. Pick the right arch:

    ARCH=$(uname -m | sed 's/x86_64/amd64/;s/aarch64/arm64/')
curl -L -o /tmp/objectio.tar.gz \
  https://github.com/object-io/objectio/releases/latest/download/objectio-linux-${ARCH}.tar.gz
sudo tar -xzf /tmp/objectio.tar.gz -C /usr/local/bin \
  objectio-aio objectio-gateway objectio-meta objectio-osd obioctl \
  objectio-install objectio-block-gateway

    Verify:

    obioctl --version
objectio-aio --help

    Runtime packages (all installed automatically as dependencies of the systemd unit on RPM/DEB-based distros, or install manually for the tarball):

    # Debian / Ubuntu
sudo apt-get install -y ca-certificates libssl3

# RHEL / Rocky / Alma 9+
sudo dnf install -y ca-certificates openssl-libs

    2. Bootstrapping a node with objectio-install¶

    objectio-install is the one-shot node bootstrapper. It prepares disks, writes config files, and optionally installs and enables systemd units. Use it for fresh metal / VMs.

    Create the service user¶

    sudo groupadd -r objectio
sudo useradd -r -g objectio -d /var/lib/objectio -s /usr/sbin/nologin objectio
sudo mkdir -p /etc/objectio /var/lib/objectio /var/log/objectio
sudo chown objectio:objectio /var/lib/objectio /var/log/objectio

    Inspect candidate disks¶

    sudo objectio-install disk list           # only unused disks
sudo objectio-install disk list --all     # everything, including mounted ones

    Output shows path, size, model, and whether the disk already contains an ObjectIO superblock. objectio-install disk prepare is destructive — it overwrites the device with a fresh superblock.

    sudo objectio-install disk prepare /dev/sdb --block-size-mb 4
sudo objectio-install disk check /dev/sdb   # verify

    Initialize the node¶

    The init subcommand generates /etc/objectio/{gateway,meta,osd}.toml and (with --systemd) installs /etc/systemd/system/objectio-*.service.

    Single-node (all roles on one box, good for edge / appliance):

    sudo objectio-install init \
  --role all \
  --disks /dev/sdb,/dev/sdc,/dev/sdd,/dev/sde,/dev/sdf,/dev/sdg \
  --ec-profile 4+2 \
  --systemd
sudo systemctl enable --now objectio-meta objectio-osd objectio-gateway

    Meta node (Raft):

    sudo objectio-install init \
  --role meta \
  --raft-peers meta1.internal:9101,meta2.internal:9101,meta3.internal:9101 \
  --systemd
sudo systemctl enable --now objectio-meta

    OSD node (storage):

    sudo objectio-install init \
  --role osd \
  --disks /dev/sdb,/dev/sdc,/dev/sdd,/dev/sde \
  --meta-endpoint http://meta1.internal:9100,http://meta2.internal:9100,http://meta3.internal:9100 \
  --systemd
sudo systemctl enable --now objectio-osd

    Gateway node (S3 API):

    sudo objectio-install init \
  --role gateway \
  --meta-endpoint http://meta1.internal:9100,http://meta2.internal:9100,http://meta3.internal:9100 \
  --systemd
sudo systemctl enable --now objectio-gateway

    Joining an existing cluster¶

    Skip config generation; point at the running meta and attach the local disks:

    sudo objectio-install join \
  --meta-endpoint http://meta1.internal:9100,http://meta2.internal:9100,http://meta3.internal:9100 \
  --disks /dev/sdb,/dev/sdc

    What gets written¶

    Path Purpose
    /etc/objectio/gateway.toml / meta.toml / osd.toml Per-service config
    /etc/systemd/system/objectio-*.service systemd units (if --systemd)
    /var/lib/objectio/{meta,osd}/ Persistent state
    /var/log/objectio/ Log output (journald in parallel)

    objectio-install status shows the current config + detected roles.

    3. Build from source¶

    Needed if you want to track main, run a custom branch, or build for an older glibc.

    Toolchain¶

    # Rust (1.93+)
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh -s -- -y
source "$HOME/.cargo/env"
rustup toolchain install 1.93

# Build deps
# Debian / Ubuntu
sudo apt-get install -y build-essential nasm autoconf automake libtool \
  libclang-dev pkg-config protobuf-compiler libprotobuf-dev cmake

# RHEL / Rocky / Alma 9+
sudo dnf install -y gcc-c++ make nasm autoconf automake libtool \
  clang-devel pkgconf protobuf-compiler protobuf-devel cmake

    NASM is only required on x86_64 — it drives ISA-L's assembly. On ARM64 omit it and drop --features isal.

    Console (SPA) prerequisites¶

    objectio-aio and the gateway's /_console/ surface embed a pre-built React bundle. If you're only building server binaries and don't need the console, nothing to do. To build the console you need Node 22+:

    # Ubuntu — NodeSource 22.x
curl -fsSL https://deb.nodesource.com/setup_22.x | sudo -E bash -
sudo apt-get install -y nodejs

cd console && npm ci && npm run build   # → console/dist

    Build¶

    git clone https://github.com/object-io/objectio
cd objectio

# amd64 — ISA-L on
cargo build --workspace --release --features isal

# arm64 — pure-Rust EC
cargo build --workspace --release

    Binaries land in target/release/. For a system install:

    sudo install -m 0755 target/release/objectio-{aio,gateway,meta,osd,cli,install,block-gateway} \
  /usr/local/bin/

    Then proceed as in section 2.

    Run the test suite¶

    cargo test --workspace --features isal
cargo clippy --workspace --all-targets --features isal -- -D warnings
cargo fmt --all -- --check
# Or the one-shot:
make ci

    Disk preparation — production checklist¶

    • [ ] Dedicate whole disks to OSDs (no partitioning, no filesystem).
    • [ ] Disable write-cache on SAS/SATA drives with non-battery-backed controllers: hdparm -W 0 /dev/sdX.
    • [ ] For NVMe, confirm the drive supports FUA (Force Unit Access) — check nvme id-ctrl -H <dev> | grep -i fua.
    • [ ] Raise /proc/sys/fs/file-max and ulimit -n (OSD opens one fd per concurrent operation × disk).
    • [ ] Pin CPUs / set tuned-adm profile throughput-performance.
    • [ ] If using io_uring, make sure the kernel is 5.15+ and /proc/sys/kernel/io_uring_disabled is 0.

    See topologies.md for how many disks and nodes to size for a given durability target.

    systemd unit reference¶

    objectio-install --systemd installs standard units. If you're bootstrapping manually, here's the skeleton for the OSD (the others are analogous — replace paths and drop the CAP_SYS_RAWIO bits for non-OSD roles):

    # /etc/systemd/system/objectio-osd.service
[Unit]
Description=ObjectIO Object Storage Daemon
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
# OSD needs raw-disk access. Use CAP_SYS_RAWIO rather than running as root.
User=objectio
Group=objectio
AmbientCapabilities=CAP_SYS_RAWIO
CapabilityBoundingSet=CAP_SYS_RAWIO
ExecStart=/usr/local/bin/objectio-osd --config /etc/objectio/osd.toml
Restart=always
RestartSec=5
LimitNOFILE=1048576
# Durability: kill -9 only after giving the OSD time to checkpoint
TimeoutStopSec=60

[Install]
WantedBy=multi-user.target

    For the gateway and meta services, drop CAP_SYS_RAWIO and keep the same shape.

    Uninstall¶

    sudo systemctl disable --now objectio-gateway objectio-meta objectio-osd
sudo rm /etc/systemd/system/objectio-{gateway,meta,osd}.service
sudo systemctl daemon-reload
sudo rm /usr/local/bin/objectio-*
# Data + config (destructive):
sudo rm -rf /etc/objectio /var/lib/objectio /var/log/objectio
sudo userdel objectio && sudo groupdel objectio

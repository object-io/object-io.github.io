    Docker¶

    ObjectIO ships a single multi-stage Dockerfile that produces six targets. You pick one image per role (three for a minimal split-role cluster, six if you want the block gateway too), or the all-in-one image for quick-test / appliance setups.

    • Fastest demo: objectio-aio container
    • Real local cluster: make cluster-up (3 meta + 6 OSD + 1 gateway, 4+2 EC)
    • Production-shaped raw disks: deploy/prod/
    • Kubernetes: see kubernetes.md

    Image targets¶

    Target Binary Ports Role
    gateway objectio-gateway 9000 S3 / Iceberg / Delta Sharing / /_console/
    meta objectio-meta 9100 (gRPC), 9101 (Raft), 9102 (admin) Raft metadata
    osd objectio-osd 9200 (gRPC), 9201 (metrics) Object storage daemon
    cli objectio-cli — Admin CLI
    block-gateway objectio-block-gateway 9300 (gRPC), 10809 (NBD) iSCSI / NBD / NVMe-oF target
    all all of the above 9000 + internal One image, any binary (AIO image)

    Port numbers are the cluster convention used by deploy/ and the Helm chart. The CLI defaults inside each binary are different (gateway/meta/osd default to 9000/9001/9002). See configuration.md for the split.

    One multi-arch image is published on GHCR, and it carries every service:

    • ghcr.io/object-io/objectio:latest (the all target)

    Each container overrides the entrypoint to pick a service — that is what the helm chart does. The per-service Dockerfile targets (gateway, meta, osd, cli, block-gateway) are not published; build them locally if you want them:

    docker build --target gateway -t objectio-gateway .

    linux/amd64 uses ISA-L for hardware-accelerated erasure coding; linux/arm64 uses pure-Rust SIMD. Mixing arches in a cluster is supported.

    All-in-one (AIO) image¶

    The all target packages every binary plus the console SPA. You choose the entrypoint at docker run time.

    # Run AIO — single-process cluster, everything on port 9000
docker run --rm -p 9000:9000 \
  -v objectio-data:/var/lib/objectio \
  ghcr.io/object-io/objectio:latest \
  objectio-aio --data /var/lib/objectio

# Same image, run the admin CLI against an existing cluster
docker run --rm --network host \
  ghcr.io/object-io/objectio:latest \
  -e OBJECTIO_ACCESS_KEY -e OBJECTIO_SECRET_KEY \
  objectio-cli --endpoint http://localhost:9000 user list

    When to use which¶

    Use AIO image Use split images
    Laptop dev, CI, demos, smoke tests Production
    Single-process topology Separate pods / nodes per role
    One binary, any subcommand Minimal attack surface per container

    Local cluster (make cluster-up)¶

    deploy/local-cluster/docker-compose.yml stands up the shape people actually run: 3 meta replicas (real Raft), 6 OSDs (for 4+2 EC), 1 gateway, 1 block-gateway, all on one Docker host.

    git clone https://github.com/object-io/objectio
cd objectio

make cluster-up          # builds images, starts the stack
make cluster-status      # docker compose ps
make cluster-logs        # tail every service
make cluster-cli ARGS="user list"    # run objectio-cli in the cluster network
make cluster-down        # stop, keep volumes
make cluster-clean       # stop + wipe volumes

    Direct docker compose also works:

    docker compose -f deploy/local-cluster/docker-compose.yml up -d
docker compose -f deploy/local-cluster/docker-compose.yml logs -f gateway

    Ports exposed on the host¶

    Host port Container Purpose
    9000 gateway:9000 S3 / Iceberg / Delta Sharing / /_console/
    9100 meta1:9100 Meta gRPC (leader usually talks here)
    9102 / 9103 meta2:9100 / meta3:9100 Meta gRPC (followers)
    9200 + 9202–9206 osd1..osd6:9200 OSD gRPC
    9300 block-gateway:9300 Block gRPC
    10809 block-gateway:10809 NBD target

    Nothing else is exposed — meta's Raft port (9101) and per-OSD metrics ports are only reachable inside the objectio-net bridge.

    Monitoring side-car¶

    An optional companion compose file layers on Prometheus + Grafana:

    docker compose \
  -f deploy/local-cluster/docker-compose.yml \
  -f deploy/local-cluster/docker-compose.monitoring.yml \
  up -d
# Grafana: http://localhost:3000  (admin / objectio)

    Production compose (raw disks)¶

    deploy/prod/docker-compose.yml is a reference for running ObjectIO on a single host with real block devices rather than volumes. Use it as a starting point for appliance builds or when Kubernetes is overkill.

    Key differences from the local-cluster compose:

    • OSDs run privileged: true with SYS_RAWIO + SYS_ADMIN. The storage engine needs O_DIRECT and ioctl BLKGETSIZE64 against raw disks, which the default Docker cap set denies.
    • Disks are passed as devices:, not volumes:.
    • DISK_MODE=raw|folder toggles between real disks and sparse file "disks" for testing.
    # Edit deploy/prod/docker-compose.yml to list your actual devices
# (/dev/nvme0n1, /dev/sdb, etc.) under each osdN's `devices:` block.

DISK_MODE=raw docker compose -f deploy/prod/docker-compose.yml up -d

    deploy/single-node-7disk/ is a worked example: a 7-disk single box, one disk per OSD container, including setup-disks.sh for mkfs/fstab prep and deploy.sh for remote SSH deployment.

    Building images locally¶

    # Single-arch, native platform
make docker                 # all targets
make docker-gateway         # just the gateway
make docker-all             # the AIO image

# Multi-arch (requires docker buildx, pushes to registry)
DOCKER_REGISTRY=ghcr.io/myorg/ DOCKER_TAG=v1.0.0 \
  make docker-multiarch

# Multi-arch local-only (current platform, loads into Docker)
make docker-multiarch-local

    Build args exposed by the Dockerfile:

    Arg Default Notes
    RUST_VERSION 1.93 Rust compiler pinned in the builder-base stage
    FEATURES auto isal on x86_64, empty on arm64. Override to force either.
    TARGETPLATFORM / TARGETARCH from buildx Set automatically by docker buildx

    Example — build a pure-Rust amd64 image (useful for platforms that lack the ISA-L nasm prereq):

    docker build --target all --build-arg FEATURES="" -t objectio:no-isal .

    Environment variables (containerised services)¶

    Most configuration goes via CLI flags in the container command: block — see the compose files in deploy/ for worked examples. A small set of settings is additionally reachable via env vars:

    Env var Service Purpose
    OBJECTIO_TOPOLOGY_REGION gateway Sets --topology-region
    OBJECTIO_TOPOLOGY_ZONE gateway Sets --topology-zone
    OBJECTIO_TOPOLOGY_DATACENTER gateway Sets --topology-datacenter
    OBJECTIO_TOPOLOGY_RACK gateway Sets --topology-rack
    OBJECTIO_TOPOLOGY_HOST gateway Sets --topology-host
    OBJECTIO_HOST_PROVIDER gateway Sets --host-provider (noop | k8s)
    OBJECTIO_HOST_PROVIDER_OSD_STS gateway OSD StatefulSet name (k8s provider only)
    POD_NAMESPACE gateway Namespace for host-provider RBAC (k8s only)
    OBJECTIO_MASTER_KEY gateway SSE-S3 master key (base64 32-byte)
    OBJECTIO_CONSOLE_DIR gateway Override the /_console/ static-asset dir
    RUST_LOG all Overrides --log-level; same syntax as tracing

    For everything else — listen address, meta endpoint, EC profile, data dir — pass flags in command:. See configuration.md for the full CLI surface.

    Health checks¶

    Built into every runtime image:

    # gateway
HEALTHCHECK CMD curl -f http://localhost:9000/health || exit 1
# meta, osd, block-gateway
HEALTHCHECK CMD /usr/local/bin/healthcheck.sh      # stub — always exits 0

    The gateway health check is the real one (queries /health which checks meta connectivity). Meta / OSD currently rely on their supervisor (compose restart policy, or K8s liveness probes in the Helm chart) to restart on crash.

    Troubleshooting¶

    "operation not permitted" on an OSD¶

    OSDs need CAP_SYS_RAWIO to open raw block devices with O_DIRECT. In docker-compose.yml:

    services:
  osd1:
    privileged: true   # easiest — or scope down to:
    cap_add: [SYS_RAWIO, SYS_ADMIN]
    devices: [/dev/sdb:/dev/sdb]

    Gateway can't reach meta¶

    Gateways and OSDs take every meta node's address in one comma-separated --meta-endpoint (for example http://meta1:9100,http://meta2:9100,http://meta3:9100); any one that answers serves them. Confirm DNS resolves inside the objectio-net bridge:

    docker compose -f deploy/local-cluster/docker-compose.yml exec gateway \
  getent hosts meta1

    "port already in use" on cluster-up¶

    Something else is bound to 9000 / 9100 / 9200–9206 / 9300 / 10809. Either stop the conflicting service or change host port mappings in the compose file.

    Quickstart¶

    The fastest path to a running ObjectIO is the all-in-one binary (objectio-aio). It runs meta + OSD + gateway as tokio tasks in a single process, shares one log stream, and is shut down with a single Ctrl-C. Same wire protocol as a real cluster — what's different is that there is no HA and no redundancy by default.

    This page covers the three fastest paths:

    Path Platform Best for
    AIO binary Linux, macOS Laptop-local S3/Iceberg/Delta endpoint
    AIO container Linux, macOS Quick CI or demo; no host Rust toolchain
    make cluster-up Linux, macOS Real 3-meta + 6-OSD + gateway topology with 4+2 EC

    ObjectIO is POSIX-only — no native Windows build. The storage engine uses O_DIRECT, ioctl BLKGETSIZE64, and other unix-only interfaces; there is no meaningful cfg-gate to Windows.

    For a production walkthrough, jump to Linux · macOS · Docker · Kubernetes.

    1. AIO binary (fastest — no Docker)¶

    Downloads a single pre-built binary from the latest GitHub release and runs it. No background services, no daemons, data in a tempdir unless you say otherwise.

    macOS (Apple Silicon)¶

    curl -L -o objectio-aio \
  https://github.com/object-io/objectio/releases/latest/download/objectio-aio-darwin-arm64
chmod +x objectio-aio && sudo mv objectio-aio /usr/local/bin/
objectio-aio

    macOS (Intel)¶

    curl -L -o objectio-aio \
  https://github.com/object-io/objectio/releases/latest/download/objectio-aio-darwin-amd64
chmod +x objectio-aio && sudo mv objectio-aio /usr/local/bin/
objectio-aio

    Linux (x86_64, with ISA-L acceleration)¶

    curl -L -o objectio-aio \
  https://github.com/object-io/objectio/releases/latest/download/objectio-aio-linux-amd64
chmod +x objectio-aio && sudo mv objectio-aio /usr/local/bin/
objectio-aio

    Linux (aarch64 / Raspberry Pi 5, pure-Rust EC)¶

    curl -L -o objectio-aio \
  https://github.com/object-io/objectio/releases/latest/download/objectio-aio-linux-arm64
chmod +x objectio-aio && sudo mv objectio-aio /usr/local/bin/
objectio-aio

    What you get¶

    On start, AIO prints its admin AK/SK and a ready-to-paste aws command:

    ┌─ ObjectIO ready ──────────────────────────────────────────────┐
│ S3 / Iceberg / Delta Sharing:  http://localhost:9000          │
│ Console:                       http://localhost:9000/_console │
│                                                               │
│ AWS_ACCESS_KEY_ID=OBJIO…                                      │
│ AWS_SECRET_ACCESS_KEY=…                                       │
└───────────────────────────────────────────────────────────────┘

    Smoke test from another terminal:

    export AWS_ACCESS_KEY_ID=...   # from the banner above
export AWS_SECRET_ACCESS_KEY=...
aws --endpoint-url http://localhost:9000 s3 mb s3://demo
echo 'hello objectio' | aws --endpoint-url http://localhost:9000 s3 cp - s3://demo/hello.txt
aws --endpoint-url http://localhost:9000 s3 cp s3://demo/hello.txt -

    Flags you'll actually use¶

    Flag Default Notes
    --port 9000 Public port. Only port the caller needs to know.
    --listen-addr 0.0.0.0 Use 127.0.0.1 to restrict to loopback.
    --data <dir> tempdir Persist data across restarts. Creates meta/, osd-N/, admin-creds.env.
    --osds <N> 1 Set to 3 to run 2+1 EC inside a single process.
    --strict-port off Fail fast on --port conflict instead of picking an ephemeral.

    Full objectio-aio --help for the complete surface.

    2. AIO container (no host toolchain, no host binary)¶

    The objectio image ("AIO" / all-in-one target) packages every binary plus the console SPA. Good for CI, demos, and any box where you don't want to install anything local.

    Pre-built image¶

    docker run --rm -p 9000:9000 \
  -v objectio-data:/var/lib/objectio \
  ghcr.io/object-io/objectio:latest objectio-aio --data /var/lib/objectio

    Build locally¶

    If the image isn't published yet (or you want the current main):

    git clone https://github.com/object-io/objectio
cd objectio
docker build --target all -t objectio:local .
docker run --rm -p 9000:9000 objectio:local objectio-aio

    The AIO image bundles objectio-gateway, objectio-meta, objectio-osd, objectio-cli, objectio-install, and objectio-block-gateway — you pick the entrypoint per run.

    ARM64 (Apple Silicon, Graviton, Raspberry Pi) runs the pure-Rust EC backend automatically; x86_64 gets ISA-L hardware acceleration. The wire format is identical — mixing arches in a cluster is fine.

    3. Real local cluster (3 meta, 6 OSDs, 4+2 EC)¶

    For a more production-shaped setup, use the Makefile helper. It builds every image and starts deploy/local-cluster/docker-compose.yml:

    git clone https://github.com/object-io/objectio
cd objectio
make cluster-up            # builds images, starts the stack

make cluster-status        # check that all 10 containers are Up
make cluster-logs          # tail everything
make cluster-logs-gateway  # just the gateway
make cluster-down          # stop, keep volumes
make cluster-clean         # stop, wipe volumes

    S3 endpoint stays at http://localhost:9000. Data is persisted in Docker volumes (cluster-clean to wipe).

    Same smoke test works:

    aws --endpoint-url http://localhost:9000 s3 mb s3://demo

    See docker.md for what's inside the compose file, how to point it at raw disks (deploy/prod/), and how to layer on the Prometheus + Grafana stack.

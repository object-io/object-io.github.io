    ObjectIO roadmap¶

    What comes next, by release. What already exists, and how far each part has been proven, is in features.md; what each release shipped is in its notes (0.1.0). When a release is cut, its items move into its notes and leave this page, so this page only ever shows what is ahead.

    Each item is one line: what will be true when it is done, which is also how it is tested. Moving an item between releases is an edit to this page, in a pull request like any other change. Each item links to its GitHub issue, and the ObjectIO project shows which are in progress.

    Last reviewed: 2026-10-20, after an external production-readiness review of the release candidate.

    Priorities¶

    1. S3: production-ready and bug-free. The product we ship first. No known bug stays open; every gap is either closed or written down as "not supported" with the reason.
    2. The storage engine core, worked on alongside S3: OSD, erasure coding, placement, meta, repair. Everything here is built once and reused by block and file; none of it is S3-specific.
    3. Data lake (Iceberg REST, Unity Catalog, Delta Sharing): next, and as important as S3 once S3 is in production.
    4. Block, then file, on the same core.

    Rule for every domain: reliability first. An acknowledgement means the data is on stable storage; nothing trades durability for speed.

    Domains¶

    Every item, feature and design belongs to one domain; the names are the same everywhere (this page, features.md, the designs, and the area: labels on issues).

    Domain What it covers
    S3 The S3 API and what is built on it: buckets, objects, versioning, lifecycle, replication, audit, Select, logging, quotas
    Core The storage engine shared by object, block and file: OSD, erasure coding, placement, meta (Raft), repair, recovery
    Data lake Iceberg REST Catalog, Unity Catalog API, Delta Sharing
    Security IAM, STS, tenants, policies, authentication, encryption and KMS, TLS between services
    Block Block volumes (NBD, gRPC)
    File File access (NFS and others)
    Platform Install and operate: Helm, objectio-aio, console, CLI, SDKs, metrics, dashboards, the release
